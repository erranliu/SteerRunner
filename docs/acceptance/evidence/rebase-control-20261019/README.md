## 接线与状态权威

固定 helper 仍只有 `original-turn`、`authentication-stop` 两种操作。查询失败仍返回原 reader 的资源结算事实，不能晋升业务成功；只有原 readiness（包含 owner、公钥）、输入和 reader_writers_absent 均核实，才允许后继查询或撤销覆盖原传输回执。查询进程未结算或来源不符时保留原请求，不创建替代 reader/control，不让后续响应覆盖唯一证据。

停止先释放原观察，沿原控制通道对账认证撤销，再经主线已有 artifact 通道请求原 helper 停止并核验签名退出，之后才关闭原业务 PTY。认证证明未核实仍停止业务原 Job，但保留原控制通道；缺签名退出则不提前关闭业务 PTY，避免销毁原私钥/唯一退出证明路径。最后分别核验原签名、原控制认证/关闭证明与完整原主机清单。被动服务退出不停止继续执行的业务；无法证明停止时不得保存 stopped。

Record/Intents/Commit/CAS 仍为唯一业务状态权威；控制检查点仅保存原传输事实，退出文件仅为主线已有签名公共证据。没有新增 Workflow 状态、队列、通用 RPC、第三方法或兼容迁移。内部 Orca state codec6、profile3，原生 readiness 沿主线 v3；初始化创建身份未知继续阻塞。
