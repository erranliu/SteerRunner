# PR #38 审查与修复验收（2026-10-20）

确认并修复以下三个问题，每项均保留修复前失败和修复后验证：

1. **创建执行器启动超出原创建期限。** 启动回调原先继承较长的外层操作超时，现限制在已固化的原创建 deadline；启动不确定后只读原回执，不启动替代执行器。新增 `TestCreationOwnerStartupUsesOriginalDeadline`。
2. **停止请求未读取迟到的原资源事实。** 停止意图早于辅助资源回执提交时，旧快照可能永久缺少精确关闭依据。现仅在原 ref、attempt、generation 和配置摘要完全相同时，将已提交的不透明 implementation 事实提供给同一停止操作；不改写持久化原意图、不恢复业务授权，也不转向其他资源。新增 SQLite 重启回归 `TestSRStopRecoversLateCreationFactsUnderOriginalIntent`，包含原资源与绑定变化的反例。
3. **缺少原终端凭据时可能误认唯一库存终端。** 原 worktree 回执未包含终端身份、调用方也未提交终端事实时，恢复曾可能接纳同一 worktree 的其他终端。现要求原终端身份或原初始终端创建回执；只有当前 inventory 的情况保持 unknown，零重复创建。新增 `TestCreationOwnerMissingTerminalReceiptNeverAdoptsInventory`，并在受控进程测试加入 `missing-terminal-receipt` 第六个窗口。
