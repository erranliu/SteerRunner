# Orca 工作区创建回执收敛 Spec

以 #109 合入后的 `main`（`9c36f366`）为基线。本机和配对远端已经共用 `creationCall` 及结构化工作区收尾。当前 `prepareWorkspace` 的首次创建分支和 `workspaceCreation` 从原创建计划恢复的分支，都要解码同一种 CLI 结果，并将原 selector、已解析 runtime 和响应绑定到 `workspaceCreation`。本 PR 只共用这一段纯数据处理。

## 输入和绑定

在现有 `orcatransport` 包中优先使用一个私有函数，接收 CLI 结果以及调用方已取得的 selector 和 runtime。保留 `decodeWorkspaceCreation` 对公开字段和已有 checkpoint 扩展字段的解码语义。响应 runtime 继续来自 CLI 外层元数据。已解析 runtime 来自首次发现或原计划，`id:` selector 的仓库 ID 仍来自该 selector。按基线保留字段覆盖条件，尤其是未取得已解析 runtime 时的原行为，避免无条件清空已有扩展字段。

| 边界 | 保留的行为 |
| --- | --- |
| 本机 | 首次按项目路径生成 `path:` selector 并验证本机 runtime，结构化路径仍核对本机启动元数据。恢复继续核对原 selector 与原项目路径。已有本机回执的可选字段仍按基线判定。 |
| 配对远端 | 首次从原配对环境的完整清单解析唯一 Git 仓库 ID，保留现有配对校验。恢复使用原计划的 `id:` selector。远端回执继续要求已解析 runtime 与响应一致，并要求原仓库 ID 非空且等于创建 worktree 的仓库 ID。 |
| 工作区 | 保留原固定名称、base、创建时 HEAD、worktree ID、instance 和路径的现有检查。后续继续按原 ID 查询和验证工作区，保留结构化会话准备及原有错误分类。发现期的确定失败仍是拒绝，创建后证据不足仍按原合同处理。 |

函数不解析目标、不执行 CLI、不改写已有回执。调用点保留当前顺序、校验及错误归属。复用已有结果与回执类型，无需新接口、新持久类型、通用目标层或创建状态机。

## 恢复与旧回执

- **已保存的回执**继续先验证外层 operation 属于原请求，再按原内部 checkpoint 格式解码。该路径直接消费原绑定，保留原字段、可选字段和历史扩展的接受与拒绝规则。原始字节按既有分支保留。进入现有重新编码路径后，即使后续查询失败，也沿用现有 checkpoint 编码。该编码保留已识别的原绑定，历史未知字段仍按基线处理。
- **只有原创建计划**时，沿原创建 owner 读取该计划对应的原输出并校验既有身份和摘要。原输出可用时走共用解码与绑定。计划、owner 结果或身份不可信时保留未知及既有证据。已经认领创建的操作不得重新发现仓库、补发 `worktree create`、启动替代 owner 或按名称接管工作区。
- **只有已持久化的只读准备证明**时，保留基线的派发边界。仅当原准备记录、尚未认领创建的证据和当前授权同时成立，原操作才可继续首次派发。授权撤销时按原规则结算。单独缺少回执或计划无法证明从未派发。
- 旧回执兼容仅覆盖当前仍可读的记录。保持 #107 的旧终端目录写入门禁和离线证明范围。原创建计划、owner 回执、运行状态、CLI 和公开合同均沿用现有格式。

## 验收

受控测试须分别覆盖本机和配对远端的首次创建、恢复原 owner 输出及读取已保存回执。验证原绑定、状态分类、旧字段兼容和写入次数。原输出丢失或身份不符时，恢复零新增创建及仓库发现。保留原确定拒绝和只读准备可继续首次派发的边界。

同一候选在本机及真实配对远端各跑一次默认 Orca Codex `execute/1`。核对一次原创建、原 selector/runtime/worktree/instance、结构化会话绑定、可信最终结果、原会话关闭和 `result-file/v1`。两端以两份固定 EXE 冷读各自原目录，通过 SteerLine 原升级排空门禁。创建故障和重启恢复由受控测试验证，真机冷读单独记为排空证据。

不修改 Orca。仓库发现、创建 owner、权限、工作流、会话 RPC、Git 审计、文件、usage、非 Orca Codex 和发布门禁保持各自现行合同。
