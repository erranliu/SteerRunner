# Orca agentSession 单次 RPC 收敛 Spec

基线为 `main` 的 `f5c417e8`，包含 #100、#105、#107 和 #108。本机和配对远端已共用结构化会话生命周期。`internal/execution/adapters/protocol/orca/agent_session.go` 的两条连接路径重复执行能力检查、一次请求及回执读取。本 PR 只收敛这段代码，在现有协议包内完成，不修改 Orca。

## 共用边界

连接取得并验证后，共用逻辑检查目标通告的能力，调用现有 `requestWithCapabilities` 一次，用原请求 ID 读取回执并关闭本次连接。首选一个私有函数，沿用 `AgentSessionClient` 和两条既有连接路径。`createSupport`、`create`、`send`、`history`、`item` 和 `close` 的公开契约、错误类别、参数、指纹、单文本块和回执验证保持原样。每次调用独立连接，保留现有超时和关闭语义。

| 边界 | 原合同 |
| --- | --- |
| 本机 | 使用原 runtime 绑定读取本机 Orca 启动元数据，通过原 named pipe 和本机认证完成 `status.get`。启动元数据或回执的 runtime 不符时拒绝。本机认证及封包仍由本机连接实现。 |
| 配对远端 | 每次调用读取显式环境的当前配对，连接前将公钥摘要与冻结的原主机身份核对。沿原加密 WebSocket 握手、设备认证及 `status.get` 验证原 runtime。主机、配对或 runtime 变化时拒绝。 |
| 能力 | 两端保留当前声明的客户端能力及其顺序和位置，远端握手与请求各保留原声明。保留本机 Codex、配对远端 Codex、本机 Pi 各自的能力集合。`createSupport` 和 `create` 沿原原子创建检查，`send` 沿原续轮检查，缺能力时该业务请求零派发。 |
| 写入 | 本机在第一字节前消费原持久派发许可。远端取得原写锁后、第一帧前重查取消和许可。认证、握手和只读请求均不消费业务派发许可。 |
| 回执 | 保留原请求 ID、runtime 和会话/回合校验，以及明确拒绝与结果未知的区分。派发后断连、超时或回执失去可信归属时，共用层返回原错误供现有生命周期处理。不得重连重发、重建会话、换目标或降级到终端。上层只沿既有原身份对账和已持久回执恢复规则处理。 |

共用层只借用连接已有的请求、回执和关闭能力。确有类型约束时，私有接缝限于当前函数所需方法；现有 `stateConnection` 的调用方不因本 PR 扩面。代码审计应能看到两处重复流程缩为一处。禁止为统一身份、能力或调用方式引入公开接口、连接池、通用重试器、注册表或跨通道 transport 框架。CLI、工作区创建、文件通道、usage、订阅 feed、Workflow、非 Orca Codex、旧 Run 离线证明和升级排空门禁均沿原实现。无远端 Pi 准入。

## 验收

- 受控测试分别覆盖本机 IPC 和配对 WebSocket。绑定错或缺能力时，相应会话业务请求零派发。已派发且丢回执时，记录原请求实际写出一次，调用方保持原未知结果，原身份对账不补发。只读请求无业务许可消耗。保留正常回执、明确拒绝、取消和错配回执的原分类。
- 同一候选源码及写入 EXE 在本机和真实配对远端各验证 Codex `execute/1` 和 `development/2`。每端验证原子多行首消息、可信最终结果、同一原会话的新一轮和显式停止。停止证明限原 `orca_agent_session` 范围，保留停止后 `result-file/v1`、恢复授权撤销及原目录升级排空。使用现行 Workflow 结果规则。
- 同一写入 EXE 在本机跑一次 Pi `development/2`，覆盖原子首消息和同一会话的 `send` 续轮，保留一次文件快照和原会话停止范围。资格限此专项，现有发布要求继续按 [测试指南](../testing.md) 执行。
