## P1 公共预算与输入事实

- 在现有 execution/model 值层增加纯 UTF-8 计量/校验与冻结摘要小函数；来源片段按调用方/Runner 归属，保留原文内部换行归属。不新增框架、DSL、运行时协议文件或输入调度器。
- 仅 R<=1000；C/T 不设正文上限但继续计量/冻结；检查最终文字，超限报告三个数及来源，不截断/摘要/拆分。
- 在原 StageInput、TurnInput、FeedbackInput 及 parser/adapter 已有记录内补缺失计数/摘要/来源；不重复建立正文存储和身份权威。

## P2 阶段提示词收敛

- 删除完整内部结果/台账/provider 配置，只保留模型任务必需事实；引用现有材料路径，发布目标不得改变。
- 固定短化正文、格式、完成引导、反馈和文件说明。progress/result 只在相关执行步骤附带说明，文件与环境生命周期不变。
- 保持审计 execute 可覆盖正文和 report 固定格式的区别；新默认文本不破坏旧 State/PromptBodies/ResultInstruction 的文字兼容。
- 内容 inline/schema 仍按最终内容计量；大 final/文件/API 结果不误套输入预算。parser 超限只拒绝候选，保留既有一次 report 获取策略。

## P3 原入口投递与公开契约

- 初始化、会话 developerInstructions/Runner 工具说明、环境检查、原生问答、独立解析及终端包装均复用公共检查；各 owner 继续装配，不跨层导入 workflow。
- 原生包装/换行先完成再检查冻结，发送前核对摘要；恢复不重复追加。旧输入可从冻结来源可靠补算时不改原文字，不能计量只拒绝新派发，观察/停止/结算保留。
- 原命令/模型桥编码和身份核验不变；实际封装/Windows 完整命令行在现有发送边界独立保护，记录依据，不扩建网络追踪。
- capabilities 发布输入预算与 owner 同源片段声明，现有支持组合/操作不删减；更新已有 Workflow 使用说明。

## P4 最小验证与交付

- 公共边界：调用方 1999/2000/2001 及长正文、总量 2999/3000/3001 及更大均可通过；Runner 999/1000/1001，中文/非 BMP/组合字符/换行/转义、单方超限及冻结后修改。
- 各输入入口接线与零超限发送；覆盖、四种文件开关、旧定义恢复、长结果程序提取、parser 有效证据与原 report 后备。
- 复用受影响 Go/Node 测试及现有受控边界，核对能力目录及四类 workflow，不运行业务测试或完整原生资格矩阵。
- 独立生产入口最小链路：初始化（按原入口）→短任务执行无副作用工具并完成→同会话发布式短指令仅返回唯一标记。绑定原问题模型/账号/SDK，未知只对账、不重发/补 Enter；现场不可用时保留具体缺口，不能冒充真实验收通过。
