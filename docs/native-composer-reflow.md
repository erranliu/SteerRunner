# 原文不变的 Codex 草稿核验

Orca 的屏幕草稿检测依靠 xterm 的行 `wrapped` 标记重建换行。
Codex 文本编辑框自行做单词折行时，屏幕行可能没有该标记；此时原空格会被投影为 LF。
这份屏幕投影不能据以修改输入，也不能把空格和换行按等价处理。

对于 Runner 新建且拥有的远端 Codex 终端，仅当差异全为显示行插入 LF 或原空格被观测为 LF，
Runner 才尝试一次拥有 PTY 的临时视口重绘（现有 `terminal.resizeForClient`，1024×80）。
随后丢弃窄视口观测，重新要求原来的逐字/合法折叠块核验和连续两次完全稳定。
真正的换行或其他字节差异仍拒绝。正文、括号粘贴字节、provider/main 基线和完整原文回执不变。

视口调用前后核对 runtime、terminal、incarnation、worktree；已有外部显示策略时拒绝。
临时 override 使用唯一 owner ID，退出时只恢复该 owner 的原尺寸，恢复回执也必须核验。
不设置账号、全局环境、全局视口偏好，不修改 Orca/SDK 包，不重发粘贴或 Enter。
视口操作仅是呈现修复，不是接受、启动或完成凭据；公开原输入及最终回执仍由原通道独立核验。

正式实验先用同一构建通过首任务和真实 publish.execute 的独立门禁，再取得长短各三个有效样本。
只有首任务有真实工具输出和规范完成，且发布原输入确已尝试粘贴，才计有效发布样本；
发布阶段失败或未知结果照实保留，前置失败单列、完整清理、有界继续新现场，绝不重放旧请求。
